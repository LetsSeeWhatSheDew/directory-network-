# Fix PuffPrice email (about 15 minutes, needs Matthew's logins)

## What's broken (found Nov 19, 2026)

- **Every PuffPrice email fails.** That covers the alert confirm email, the Monday report, deal alerts and Green Wednesday emails.
  - Proof: a real signup on production with `hi@puffprice.com` returned `HTTP 502`, code `resend_403_validation_error` (`scripts/alert-signup-probe.mjs`, GitHub Actions run 44577259858).
  - Resend answers 403 `validation_error` when the sending domain isn't verified.
- **This is why there are 0 alert subscribers.** Nobody can finish signing up.
- **Cause:** `send.puffprice.com` has no MX record. DNS read from GitHub Actions on Nov 19 showed it empty. Resend needs that record to verify the domain:
  - The DKIM record (`resend._domainkey`) is present.
  - The SPF record on `send` is present.
  - Only the MX is missing.
- **Why it was never added:** Namecheap only allows MX records in **Custom MX** mode. Switching to that mode turns off Namecheap **Email Forwarding**, which is what `hi@puffprice.com` uses today: MX = eforward1–5.registrar-servers.com.

**Fix:** switch to Custom MX, add Resend's MX, and move `hi@` forwarding to ImprovMX (free).

## Try first: Path A, no MX and no ImprovMX (about 5 minutes, added Nov 25)

Resend now offers a CNAME setup ("Resend Forge" / newer domains) that replaces the MX on `send`. Namecheap allows CNAME records in Email Forwarding mode, so `hi@` forwarding stays exactly as it is. This comes from Resend's docs and is UNVERIFIED for this account; if Resend doesn't offer it on `puffprice.com`, use Path B below.

1. **resend.com → Domains → puffprice.com.**
   - Look for the CNAME migration ("Forge").
   - Or open **Advanced options**, set the Return-Path subdomain to `bounce`, so it doesn't clash with the TXT already on `send`.
2. **Namecheap → Advanced DNS:** add the CNAME record(s) Resend shows, exactly as shown. The Host goes in without `.puffprice.com`. Leave Mail Settings on **Email Forwarding**, and leave every other record alone.
3. **Resend:** click Verify. It's usually green within 15 minutes.
4. **Tell Claude.** Claude runs the "Alert signup probe", and the queued signup's confirm goes out with the next daily retry.

## Path B: the MX route (the original plan)

## Steps

### 1. ImprovMX (forwarding for hi@), about 3 minutes

1. Go to improvmx.com and add the domain `puffprice.com`.
2. Set the forward: `hi` → the inbox you want PuffPrice mail in.
3. Add a catch-all `*` → the same inbox, so `partnerships@` and others also land.
4. Leave the page open. It shows the two MX records and one SPF record to add.

### 2. Resend (copy the exact MX value), about 1 minute

1. Go to resend.com → Domains → `puffprice.com`.
2. Find the **MX** record for host `send`. Its value looks like `feedback-smtp.us-east-1.amazonses.com`; copy the exact one shown, since the region matters.

### 3. Namecheap → Domain List → puffprice.com → Advanced DNS, about 5 minutes

1. **Mail Settings:** change "Email Forwarding" to **Custom MX**.
2. Add these MX records. Namecheap's priority column is the unlabeled one after Value.

   | Host | Value | Priority |
   |---|---|---|
   | `@` | `mx1.improvmx.com` | 10 |
   | `@` | `mx2.improvmx.com` | 20 |
   | `send` | (the value from Resend) | 30 |

3. Add TXT `@` = `v=spf1 include:spf.improvmx.com ~all`. There's no root SPF today.
4. Don't touch the records for the website (A/CNAME for `@` and `www`), `resend._domainkey`, the TXT on `send`, or `google-site-verification`.
5. Save all.

### 4. Check, about 5 minutes

1. ImprovMX shows its records as valid.
2. In Resend, click Verify on `puffprice.com`. It usually turns green within 15 minutes (Resend says it can take up to 72 hours).
3. Tell Claude. Claude re-runs the "Alert signup probe" on GitHub, and a pass reads `HTTP 200 {"ok":true,"status":"pending"}`.
4. The confirm email for `hi@puffprice.com` will then arrive in the inbox you chose in step 1. That one email proves sending and forwarding together.
